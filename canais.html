Canais: mensagens entre threads

Em vez de várias threads mexerem no mesmo dado, elas podem trocar mensagens. Um canal tem duas pontas: quem envia (Sender, o transmissor) e quem recebe (Receiver). O módulo da biblioteca padrão é std::sync::mpsc: multiple producer, single consumer (vários produtores, um consumidor).

1. Primeiro canal

use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    thread::spawn(move || {
        let msg = String::from("pedido 17 pronto");
        tx.send(msg).unwrap();
    });

    let recebido = rx.recv().unwrap();
    println!("recebi: {recebido}");
}

mpsc::channel()
cria o canal e devolve (Sender, Receiver); por costume, tx e rx.
tx.send(v)
envia v; a posse do valor vai junto.
rx.recv()
espera (bloqueia) até chegar uma mensagem.

2. Recebendo várias mensagens

use std::sync::mpsc;
use std::thread;
use std::time::Duration;

fn main() {
    let (tx, rx) = mpsc::channel();

    thread::spawn(move || {
        for etapa in ["baixando", "descompactando", "instalando"] {
            tx.send(etapa).unwrap();
            thread::sleep(Duration::from_millis(20));
        }
    });

    for msg in rx {
        println!("status: {msg}");
    }
    println!("canal fechado");
}

3. Vários produtores

use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    for id in 1..=3 {
        let tx = tx.clone();
        thread::spawn(move || {
            let quadrado = id * id;
            tx.send((id, quadrado)).unwrap();
        });
    }
    drop(tx);

    let mut resultados: Vec<(i32, i32)> = rx.iter().collect();
    resultados.sort();
    for (id, q) in resultados {
        println!("trabalhador {id} mandou {q}");
    }
}

Cada thread recebe seu próprio clone do Sender. O drop(tx) é importante: o tx original também conta como produtor, e sem soltá-lo o canal nunca fecharia e o collect ficaria esperando para sempre. As mensagens chegam em ordem imprevisível; por isso o sort.

4. Sem bloquear: try_recv e recv_timeout

use std::sync::mpsc;
use std::thread;
use std::time::Duration;

fn main() {
    let (tx, rx) = mpsc::channel::<u32>();

    println!("{:?}", rx.try_recv());

    let h = thread::spawn(move || {
        thread::sleep(Duration::from_millis(50));
        tx.send(99).unwrap();
    });

    println!("{:?}", rx.recv_timeout(Duration::from_millis(5)));
    println!("{:?}", rx.recv_timeout(Duration::from_secs(1)));
    h.join().unwrap();
    println!("{:?}", rx.try_recv());
}

recv()espera; Err só se o canal fechou
try_recv()volta na hora com Err(Empty), ou Err(Disconnected) se fechou
recv_timeout(d)espera até d; depois Err(Timeout)
sync_channel(n) cria um canal com espaço para no máximo n mensagens: quando ele enche, send espera. Útil para o produtor não andar muito à frente do consumidor.

use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel::<i32>();
    thread::spawn(move || {
        let _ = tx;
    });
    for n in rx {
        println!("recebi: {n}");
    }
}

Missão: Três threads mandam 10, 20 e 30. O programa trava porque o canal nunca fecha. Conserte para imprimir total: 60.

use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();
    for v in [10, 20, 30] {
        let tx = tx.clone();
        thread::spawn(move || tx.send(v).unwrap());
    }
    let total: i32 = rx.iter().sum();
    println!("total: {total}");
}

use std::thread;

Resumo

  • mpsc::channel() devolve (tx, rx); send envia e move o valor, recv espera.
  • for msg in rx recebe até o canal fechar.
  • Vários produtores: tx.clone() para cada thread, e drop(tx) no original.
  • try_recv e recv_timeout não ficam presos esperando.
