unsafe básico

O compilador do Rust é conservador: prefere recusar um programa correto a aceitar um perigoso. Às vezes, porém, você sabe algo que ele não consegue provar, ou precisa conversar com o hardware ou com código em C. Para isso existe unsafe: um bloco em que você assume a responsabilidade por algumas regras.

unsafe não desliga o borrow checker. Ele libera só cinco “superpoderes”: (1) desreferenciar ponteiros crus; (2) chamar funções unsafe (incluindo funções de C); (3) ler e escrever static mut; (4) implementar traits unsafe; (5) acessar campos de union. Todo o resto continua checado.

1. Ponteiros crus

fn main() {
    let mut numero = 10;

    let r1 = &raw const numero;
    let r2 = &raw mut numero;

    unsafe {
        *r2 += 5;
        println!("r1 aponta para {}", *r1);
    }
    println!("numero = {numero}");
}

&raw const e &raw mut criam ponteiros crus (*const i32 e *mut i32). Criar é seguro; usar (*r1) exige unsafe, porque o compilador não garante que o ponteiro é válido. Repare que aqui temos um ponteiro de leitura e um de escrita ao mesmo tempo, algo que referências normais nunca permitiriam.

fn main() {
    let numero = 10;
    let p = &raw const numero;
    println!("{}", *p);
}

2. Funções unsafe

/// Devolve o elemento sem checar o índice.
///
/// # Safety
/// `i` precisa ser menor que `v.len()`.
unsafe fn pegar_sem_checar(v: &[i32], i: usize) -> i32 {
    unsafe { *v.as_ptr().add(i) }
}

fn main() {
    let dados = [10, 20, 30];
    let x = unsafe { pegar_sem_checar(&dados, 2) };
    println!("x = {x}");
    let y = unsafe { dados.get_unchecked(0) };
    println!("y = {y}");
}
$ cargo run
   Compiling funcao-unsafe v0.1.0 (/home/ana/projetos/funcao-unsafe)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/funcao-unsafe`
x = 30
y = 10

Uma unsafe fn tem regras que quem chama precisa cumprir; por convenção, elas ficam documentadas na seção /// # Safety. A biblioteca padrão tem várias, como get_unchecked, que pula a checagem de limites.

3. Abstração segura: split_at_mut

O uso mais importante de unsafe é construir funções seguras por fora. Exemplo clássico: dividir um slice mutável em duas metades. Com referências normais o borrow checker recusa, porque vê dois empréstimos mutáveis do mesmo slice:

fn dividir(v: &mut [i32], meio: usize) -> (&mut [i32], &mut [i32]) {
    (&mut v[..meio], &mut v[meio..])
}

fn main() {
    let mut v = [1, 2, 3, 4];
    let (a, b) = dividir(&mut v, 2);
    println!("{:?} {:?}", a, b);
}
$ cargo run

Nós sabemos que as duas partes não se sobrepõem. Com ponteiros crus, dá para dizer isso ao compilador:

use std::slice;

fn dividir(v: &mut [i32], meio: usize) -> (&mut [i32], &mut [i32]) {
    let tamanho = v.len();
    assert!(meio <= tamanho);
    let p = v.as_mut_ptr();
    unsafe {
        (
            slice::from_raw_parts_mut(p, meio),
            slice::from_raw_parts_mut(p.add(meio), tamanho - meio),
        )
    }
}

fn main() {
    let mut v = [1, 2, 3, 4, 5];
    let (a, b) = dividir(&mut v, 2);
    a[0] = 100;
    b[0] = 300;
    println!("{:?}", v);
}
$ cargo run
   Compiling dividir-unsafe v0.1.0 (/home/ana/projetos/dividir-unsafe)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/dividir-unsafe`

A função dividir é segura para quem chama: o assert! garante a regra de que o unsafe precisa. É assim que a própria split_at_mut da biblioteca padrão é implementada.

4. Chamando C e static mut

unsafe extern "C" {
    safe fn abs(x: i32) -> i32;
    fn strlen(s: *const std::ffi::c_char) -> usize;
}

static mut CONTADOR: u32 = 0;

fn contar() {
    unsafe {
        CONTADOR += 1;
    }
}

fn main() {
    println!("abs(-7) = {}", abs(-7));
    let texto = c"olá";
    let n = unsafe { strlen(texto.as_ptr()) };
    println!("strlen = {n} bytes");

    contar();
    contar();
    let total = unsafe { CONTADOR };
    println!("CONTADOR = {total}");
}
$ cargo run
   Compiling extern-c v0.1.0 (/home/ana/projetos/extern-c)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/extern-c`
abs(-7) = 7
strlen = 4 bytes
CONTADOR = 2

O bloco extern "C" declara funções da biblioteca C. Funções marcadas safe podem ser chamadas sem unsafe; as outras não. c"olá" é uma string de C (terminada em zero); strlen conta 4 bytes porque á ocupa 2 em UTF-8. Já static mut é uma variável global modificável: qualquer acesso é unsafe, porque duas threads poderiam mexer nela ao mesmo tempo. Na prática, prefira um atômico ou um Mutex.

Missão: O código não compila (E0133): desreferenciar um ponteiro cru exige um bloco unsafe. Conserte para imprimir valor = 42.

fn main() {
    let mut x = 41;
    let p = &raw mut x;
    *p += 1;
    println!("valor = {x}");
}

fn main() {
    let mut x = 41;
    let p = &raw mut x;
    unsafe {
        *p += 1;
    }
    println!("valor = {x}");
}

fn main() {
    let dados = [1, 2, 3, 4, 5];
    let p = dados.as_ptr();
    let _ = p;
    println!("{:?}", &dados[..]);
}

fn main() {
    let dados = [1, 2, 3, 4, 5];
    let p = dados.as_ptr();
    let fim = unsafe { std::slice::from_raw_parts(p.add(2), 3) };

Resumo

  • unsafe libera cinco operações; o resto das regras continua valendo.
  • Ponteiros crus (*const, *mut) podem ser criados livremente, mas só desreferenciados em unsafe.
  • unsafe fn tem regras para quem chama; documente-as em /// # Safety.
  • Bom unsafe é pequeno e escondido atrás de uma API segura.
