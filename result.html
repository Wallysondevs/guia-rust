Result e panic!

Rust separa os erros em dois tipos. Os irrecuperáveis (um bug, um índice impossível) param o programa com panic!. Os recuperáveis (arquivo que não existe, texto que não é número) são valores do tipo Result<T, E>, que o seu código é obrigado a tratar.

Você vai aprender
  • Quando usar panic! e o que ele mostra.
  • Result<T, E> com Ok e Err, e como tratar com match.
  • Erros reais de parse e de leitura de arquivo, e um tipo de erro próprio.

1. panic!: parar tudo

fn main() {
    println!("antes");
    panic!("algo impossível aconteceu");
}

O panic imprime a mensagem, o arquivo e a linha, e encerra o programa com código de saída diferente de zero. Rodando com RUST_BACKTRACE=1, ele mostra também o caminho de chamadas até ali.

2. Result<T, E>

enum Result<T, E> {
    Ok(T),   // deu certo, com o valor do tipo T
    Err(E),  // deu errado, com o erro do tipo E
}
fn main() {
    let textos = ["42", "-7", "abc", ""];
    for t in textos {
        match t.parse::<i32>() {
            Ok(n) => println!("'{t}' -> número {n}"),
            Err(e) => println!("'{t}' -> erro: {e}"),
        }
    }
}
$ cargo run
   Compiling parse v0.1.0 (/home/ana/projetos/parse)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/parse`
'42' -> número 42
'-7' -> número -7
'abc' -> erro: invalid digit found in string
'' -> erro: cannot parse integer from empty string

O parse devolve Result<i32, ParseIntError>. As mensagens de erro (invalid digit found in string, cannot parse integer from empty string) vêm da própria biblioteca padrão.

3. Lendo um arquivo

use std::fs;

fn main() {
    match fs::read_to_string("notas.txt") {
        Ok(conteudo) => print!("notas.txt: {conteudo}"),
        Err(e) => println!("não li notas.txt: {e}"),
    }
    match fs::read_to_string("nao-existe.txt") {
        Ok(conteudo) => print!("{conteudo}"),
        Err(e) => println!("não li nao-existe.txt: {e}"),
    }
}

5. Atalhos: unwrap_or, unwrap_or_else, map_err

fn main() {
    let a: i32 = "abc".parse().unwrap_or(0);
    println!("a = {a}");
    let b: i32 = "xyz".parse().unwrap_or_else(|e| {
        println!("aviso: {e}");
        -1
    });
    println!("b = {b}");
    let c: Result<i32, String> = "7x".parse::<i32>().map_err(|e| format!("entrada ruim: {e}"));
    println!("{:?}", c);
    println!("{}", "5".parse::<i32>().is_ok());
}

6. Seu próprio tipo de erro

#[derive(Debug)]
enum ErroSaque {
    SaldoInsuficiente { saldo: u32, pedido: u32 },
    ValorZero,
}

fn sacar(saldo: u32, valor: u32) -> Result<u32, ErroSaque> {
    if valor == 0 {
        return Err(ErroSaque::ValorZero);
    }
    if valor > saldo {
        return Err(ErroSaque::SaldoInsuficiente { saldo, pedido: valor });
    }
    Ok(saldo - valor)
}

fn main() {
    println!("{:?}", sacar(100, 30));
    println!("{:?}", sacar(100, 0));
    match sacar(100, 250) {
        Ok(resto) => println!("sobrou {resto}"),
        Err(ErroSaque::SaldoInsuficiente { saldo, pedido }) => {
            println!("faltam {} (saldo {saldo}, pedido {pedido})", pedido - saldo)
        }
        Err(e) => println!("erro: {:?}", e),
    }
}
$ cargo run
   Compiling erro-proprio v0.1.0 (/home/ana/projetos/erro-proprio)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.08s
     Running `target/debug/erro-proprio`
Ok(70)
Err(ValorZero)
faltam 150 (saldo 100, pedido 250)

Um enum de erros deixa claro, no tipo, tudo que pode dar errado, e o match obriga quem chama a pensar em cada caso.

Resumo

  • panic! para bugs; Result<T, E> para erros esperados.
  • Trate com match (Ok(v) / Err(e)) ou com atalhos como unwrap_or e map_err.
  • Um enum de erros documenta, no tipo, o que pode dar errado.
