Generics

Generics (tipos genéricos) deixam você escrever uma função ou struct uma vez só e usá-la com vários tipos. Você já usou muitos: Vec<T>, Option<T>, Result<T, E>. O T é um “tipo a definir”, que o compilador troca pelo tipo de verdade em cada uso.

Você vai aprender
  • A escrever funções genéricas com <T> e a restringir T com traits (trait bounds).
  • O erro real quando falta a restrição, e a cláusula where.
  • Structs e blocos impl genéricos.

1. O problema: código repetido

Sem generics, achar o maior de uma lista exige uma função por tipo:

fn maior_i32(lista: &[i32]) -> i32 { /* … */ }
fn maior_f64(lista: &[f64]) -> f64 { /* … o mesmo código … */ }
fn maior_char(lista: &[char]) -> char { /* … de novo … */ }

2. Uma função genérica (e o erro de primeira)

fn maior<T>(lista: &[T]) -> &T {
    let mut maior = &lista[0];
    for item in lista {
        if item > maior {
            maior = item;
        }
    }
    maior
}

fn main() {
    println!("{}", maior(&[34, 50, 25]));
}

O compilador não deixa: um T qualquer pode não saber se comparar com >. O help diz a solução: exigir que T implemente PartialOrd (o trait das comparações < e >).

fn maior<T: PartialOrd>(lista: &[T]) -> &T {
    let mut maior = &lista[0];
    for item in lista {
        if item > maior {
            maior = item;
        }
    }
    maior
}

fn main() {
    println!("{}", maior(&[34, 50, 25]));
    println!("{}", maior(&[1.5, 0.2, 9.9]));
    println!("{}", maior(&['r', 'u', 's', 't']));
    println!("{}", maior(&["pera", "uva", "abacaxi"]));
}

3. Várias restrições e where

use std::fmt::Display;

fn mostrar_maior<T>(a: T, b: T)
where
    T: PartialOrd + Display,
{
    if a > b {
        println!("{a} é maior que {b}");
    } else {
        println!("{b} é maior ou igual a {a}");
    }
}

fn main() {
    mostrar_maior(3, 7);
    mostrar_maior("zebra", "abelha");
}
$ cargo run
   Compiling where v0.1.0 (/home/ana/projetos/where)

7 é maior ou igual a 3

T: PartialOrd + Display exige os dois traits. Quando as restrições ficam longas, a cláusula where depois da assinatura deixa tudo mais legível.

4. Structs e impl genéricos

#[derive(Debug)]
struct Par<T> {
    a: T,
    b: T,
}

impl<T: PartialOrd + Copy> Par<T> {
    fn maior(&self) -> T {
        if self.a > self.b { self.a } else { self.b }
    }
}

impl Par<f64> {
    fn media(&self) -> f64 {
        (self.a + self.b) / 2.0
    }
}

#[derive(Debug)]
struct Caixa<T, U> {
    rotulo: T,
    conteudo: U,
}

fn main() {
    let p = Par { a: 3, b: 9 };
    println!("{:?}: maior {}", p, p.maior());
    let q = Par { a: 2.0, b: 5.0 };
    println!("maior {}, média {}", q.maior(), q.media());
    let c = Caixa { rotulo: "nota", conteudo: 9.5 };
    println!("{:?}", c);
    println!("{} = {}", c.rotulo, c.conteudo);
}
$ cargo run

O impl<T: …> Par<T> vale para todo Par cujo T cumpra as restrições. Já o impl Par<f64> só existe para Par de f64: um Par<i32> não tem media. A Caixa mostra que dá para ter mais de um tipo genérico.

Generics não custam nada na execução

O compilador gera uma cópia da função para cada tipo usado (monomorfização). maior::<i32> e maior::<f64> viram duas funções normais, tão rápidas quanto se você tivesse escrito cada uma.

    T: Display,
{
    v.iter().map(|x| format!("[{x}]")).collect::<Vec<_>>().join(" ")

Resumo

  • fn f<T>(x: T), struct S<T>, impl<T> S<T> declaram generics.
  • Restrinja com traits: T: PartialOrd + Display, ou com where.
  • Sem a restrição, o compilador recusa operações que T pode não ter.
  • Generics são resolvidos na compilação: zero custo na execução.
