async/await básico

Threads são ótimas para trabalho pesado de CPU. Para programas que passam a maior parte do tempo esperando (rede, disco, temporizadores), o Rust oferece async/await: muitas tarefas podem esperar ao mesmo tempo sem uma thread para cada uma. Nesta aula você vai entender como isso funciona por dentro, usando só a biblioteca padrão.

A diferença do Rust: a linguagem traz async, .await e o trait Future, mas não traz um executor (quem roda as futures). Em projetos reais se usa um runtime pronto, como o tokio. Aqui vamos escrever um executor mínimo para ver as engrenagens.

1. Uma future não faz nada sozinha

2. O trait Future e o poll

Por dentro, uma future é algo que sabe responder à pergunta “já terminou?”:

pub trait Future {
    type Output;
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}

pub enum Poll<T> {
    Ready(T),
    Pending,
}
poll
o executor chama para fazer a future andar.
Poll::Ready(v)
terminou, e o resultado é v.
Poll::Pending
ainda não; a future promete avisar quando valer a pena tentar de novo.
Context / Waker
o jeito de avisar: a future guarda o Waker e chama wake() quando tiver novidade.
Pin
garante que a future não mude de lugar na memória enquanto está sendo executada.

3. Um executor de 20 linhas

O block_on abaixo roda uma future até o fim na thread atual: chama poll; se vier Pending, dorme (thread::park) até alguém chamar wake, que acorda a thread (unpark).

use std::future::Future;
use std::pin::pin;
use std::sync::Arc;
use std::task::{Context, Poll, Wake, Waker};
use std::thread::{self, Thread};

struct Acordador(Thread);

impl Wake for Acordador {
    fn wake(self: Arc<Self>) {
        self.0.unpark();
    }
}

fn block_on<F: Future>(fut: F) -> F::Output {
    let mut fut = pin!(fut);
    let waker = Waker::from(Arc::new(Acordador(thread::current())));
    let mut cx = Context::from_waker(&waker);
    loop {
        match fut.as_mut().poll(&mut cx) {
            Poll::Ready(v) => return v,
            Poll::Pending => thread::park(),
        }
    }
}

async fn dobro(x: u32) -> u32 {
    x * 2
}

async fn calcular() -> u32 {
    let a = dobro(10).await;
    let b = dobro(a).await;
    println!("a = {a}, b = {b}");
    a + b
}

fn main() {
    let total = block_on(calcular());
    println!("total = {total}");
}

Dentro de calcular, cada .await espera a outra future terminar e pega o resultado, como uma chamada normal. A diferença é que, se alguma delas estivesse esperando algo de fora, a tarefa toda devolveria Pending sem travar a thread.

4. Uma future feita à mão: um temporizador

Agora uma future que de fato espera. Ela pede a uma thread auxiliar para dormir e, quando o tempo passa, chama o Waker.

use std::future::Future;
use std::pin::{pin, Pin};
use std::sync::{Arc, Mutex};
use std::task::{Context, Poll, Wake, Waker};
use std::thread::{self, Thread};
use std::time::{Duration, Instant};

struct Acordador(Thread);

impl Wake for Acordador {
    fn wake(self: Arc<Self>) {
        self.0.unpark();
    }
}

fn block_on<F: Future>(fut: F) -> F::Output {
    let mut fut = pin!(fut);
    let waker = Waker::from(Arc::new(Acordador(thread::current())));
    let mut cx = Context::from_waker(&waker);
    let mut polls = 0;
    loop {
        polls += 1;
        match fut.as_mut().poll(&mut cx) {
            Poll::Ready(v) => {
                println!("[executor] terminou depois de {polls} chamadas a poll");
                return v;
            }
            Poll::Pending => thread::park(),
        }
    }
}

struct Estado {
    pronto: bool,
    waker: Option<Waker>,
}

struct Temporizador {
    estado: Arc<Mutex<Estado>>,
}

impl Temporizador {
    fn novo(tempo: Duration) -> Self {
        let estado = Arc::new(Mutex::new(Estado { pronto: false, waker: None }));
        let e = Arc::clone(&estado);
        thread::spawn(move || {
            thread::sleep(tempo);
            let mut e = e.lock().unwrap();
            e.pronto = true;
            if let Some(w) = e.waker.take() {
                w.wake();
            }
        });
        Temporizador { estado }
    }
}

impl Future for Temporizador {
    type Output = ();
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<()> {
        let mut e = self.estado.lock().unwrap();
        if e.pronto {
            Poll::Ready(())
        } else {
            e.waker = Some(cx.waker().clone());
            Poll::Pending
        }
    }
}

async fn tarefa() -> &'static str {
    println!("esperando 100 ms...");
    Temporizador::novo(Duration::from_millis(100)).await;
    println!("esperando mais 50 ms...");
    Temporizador::novo(Duration::from_millis(50)).await;
    "pronto"
}

fn main() {
    let inicio = Instant::now();
    let r = block_on(tarefa());
    println!("{r} em pelo menos {} ms", inicio.elapsed().as_millis() / 50 * 50);
}

Foram 3 chamadas a poll: a primeira parou no primeiro temporizador, a segunda no segundo e a terceira terminou. Entre elas, a thread principal ficou dormindo, sem gastar CPU, até o Waker chamar. É esse o truque de todo runtime async: dormir até ser acordado.

5. Na prática: tokio

Num projeto real você não escreve o executor. O mais usado é o tokio, que roda milhares de tarefas e já traz temporizadores, rede e arquivos assíncronos:

Num projeto criado com cargo new relogios, com este src/main.rs:

use std::time::{Duration, Instant};
use tokio::time::sleep;

async fn tarefa(nome: &str, ms: u64) -> String {
    sleep(Duration::from_millis(ms)).await;
    format!("{nome} terminou")
}

#[tokio::main(flavor = "current_thread")]
async fn main() {
    let inicio = Instant::now();
    let (a, b, c) = tokio::join!(
        tarefa("A", 300),
        tarefa("B", 200),
        tarefa("C", 100),
    );
    println!("{a}, {b}, {c}");
    println!("tempo total: ~{} ms", inicio.elapsed().as_millis() / 100 * 100);
}

use std::future::Future;
use std::pin::{pin, Pin};
use std::sync::Arc;
use std::task::{Context, Poll, Wake, Waker};
use std::thread::{self, Thread};

struct Acordador(Thread);

impl Wake for Acordador {
    fn wake(self: Arc<Self>) {
        self.0.unpark();
    }
}

fn block_on<F: Future>(fut: F) -> F::Output {
    let mut fut = pin!(fut);
    let waker = Waker::from(Arc::new(Acordador(thread::current())));
    let mut cx = Context::from_waker(&waker);
    loop {
        match fut.as_mut().poll(&mut cx) {
            Poll::Ready(v) => return v,
            Poll::Pending => thread::park(),
        }
    }
}

struct Teimosa {
    tentativas: u32,
}

impl Future for Teimosa {
    type Output = u32;
    fn poll(mut self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<u32> {
        self.tentativas += 1;
        let _ = cx;
        Poll::Ready(self.tentativas)
    }
}

fn main() {
    let n = block_on(Teimosa { tentativas: 0 });
    println!("pronto depois de {n} tentativas");
}

Resumo

  • async fn devolve uma Future; nada roda até alguém fazer poll (direto ou via .await).
  • poll devolve Ready(v) ou Pending; com Pending, a future guarda o Waker e avisa depois.
  • Um executor chama poll e dorme entre as chamadas; o Rust não traz um, mas dá para escrever um com std::task::Wake.
  • Na prática, use um runtime como o tokio (#[tokio::main], tokio::join!).
