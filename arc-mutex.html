Arc e Mutex

Canais passam dados de uma thread para outra. Às vezes, porém, várias threads precisam mexer no mesmo dado: um contador, um cache, uma lista de resultados. Para isso, o Rust usa dois tipos juntos: Mutex garante que só uma thread mexa por vez, e Arc deixa várias threads serem donas do mesmo Mutex.

1. Mutex sozinho

use std::sync::Mutex;

fn main() {
    let m = Mutex::new(5);
    {
        let mut num = m.lock().unwrap();
        *num += 1;
    }
    println!("m = {:?}", m);
    println!("valor = {}", m.lock().unwrap());
}

espera até conseguir a trava e devolve um MutexGuard (dentro de um Result, que só é Err se outra thread entrou em pânico segurando a trava).
fim do escopo
o MutexGuard é destruído e a trava é liberada sozinha.

2. Rc não serve entre threads

use std::rc::Rc;
use std::sync::Mutex;
use std::thread;

fn main() {
    let contador = Rc::new(Mutex::new(0));
    let c = Rc::clone(&contador);
    let h = thread::spawn(move || {
        *c.lock().unwrap() += 1;
    });
    h.join().unwrap();
}

3. Arc<Mutex<T>>

Arc (atomically reference counted) é o Rc com contador atômico, seguro entre threads.

use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let contador = Arc::new(Mutex::new(0));
    let mut handles = vec![];

    for _ in 0..10 {
        let c = Arc::clone(&contador);
        handles.push(thread::spawn(move || {
            for _ in 0..1000 {
                *c.lock().unwrap() += 1;
            }
        }));
    }

    for h in handles {
        h.join().unwrap();
    }
    println!("resultado: {}", *contador.lock().unwrap());
}

Juntando resultados num Vec compartilhado

use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let achados = Arc::new(Mutex::new(Vec::new()));
    let handles: Vec<_> = (0..4)
        .map(|parte| {
            let achados = Arc::clone(&achados);
            thread::spawn(move || {
                for n in parte * 25 + 1..=parte * 25 + 25 {
                    if n % 17 == 0 {
                        achados.lock().unwrap().push(n);
                    }
                }
            })
        })
        .collect();

    for h in handles {
        h.join().unwrap();
    }
    let mut v = achados.lock().unwrap().clone();
    v.sort();
    println!("múltiplos de 17 até 100: {:?}", v);
}

4. Outras ferramentas

RwLock: muitos leitores ou um escritor

use std::sync::{Arc, RwLock};
use std::thread;

fn main() {
    let config = Arc::new(RwLock::new(String::from("modo=normal")));

    let leitores: Vec<_> = (1..=3)
        .map(|i| {
            let c = Arc::clone(&config);
            thread::spawn(move || {
                let tamanho = c.read().unwrap().len();
                (i, tamanho)
            })
        })
        .collect();
    for h in leitores {
        let (i, t) = h.join().unwrap();
        println!("leitor {i} leu {t} caracteres");
    }

    *config.write().unwrap() = String::from("modo=turbo");
    println!("config: {}", config.read().unwrap());
}

Atômicos: contadores sem trava

use std::sync::atomic::{AtomicUsize, Ordering};
use std::sync::Arc;
use std::thread;

fn main() {
    let visitas = Arc::new(AtomicUsize::new(0));
    let hs: Vec<_> = (0..8)
        .map(|_| {
            let v = Arc::clone(&visitas);
            thread::spawn(move || {
                for _ in 0..500 {
                    v.fetch_add(1, Ordering::Relaxed);
                }
            })
        })
        .collect();
    for h in hs {
        h.join().unwrap();
    }
    println!("visitas: {}", visitas.load(Ordering::Relaxed));
}

Para um número simples, AtomicUsize, AtomicBool e afins são mais leves que um Mutex.

Deadlock: o compilador impede corridas de dados, mas não impede deadlock. Se a thread A tranca o mutex 1 e espera o 2, enquanto a B tranca o 2 e espera o 1, as duas ficam paradas para sempre. Regra prática: segure a trava pelo menor tempo possível e tranque vários mutex sempre na mesma ordem.

Missão: Quatro threads somam 100 cada uma num contador compartilhado. O código usa Rc e não compila. Troque para Arc<Mutex<i32>> e imprima total: 400.

use std::rc::Rc;
use std::sync::Mutex;
use std::thread;

fn main() {
    let total = Rc::new(Mutex::new(0));
    let mut hs = vec![];
    for _ in 0..4 {
        let t = Rc::clone(&total);
        hs.push(thread::spawn(move || {
            for _ in 0..100 {
                *t.lock().unwrap() += 1;
            }
        }));
    }
    for h in hs {
        h.join().unwrap();
    }
    println!("total: {}", total.lock().unwrap());
}

use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let quadrados = Arc::new(Mutex::new(Vec::new()));
    let mut hs = vec![];
    for n in 1..=3 {
        let q = Arc::clone(&quadrados);
        hs.push(thread::spawn(move || {
            let _ = (q, n * n);
        }));
    }
    for h in hs {
        h.join().unwrap();
    }
    let mut v: Vec<i32> = quadrados.lock().unwrap().clone();
    v.sort();
    println!("{:?}", v);
}

Resumo

  • Mutex deixa uma thread por vez acessar o dado; lock() tranca e o fim do escopo destranca.
  • Rc não é Send; entre threads use Arc.
  • Arc<Mutex<T>> é o padrão para estado compartilhado e modificável.
  • RwLock para muitas leituras; atômicos para contadores simples.
