RefCell<T>: mutabilidade interior

As regras de empréstimo (uma &mut ou várias &) normalmente são checadas pelo compilador. O RefCell<T> move essa checagem para o tempo de execução: ele deixa modificar o valor mesmo através de uma referência imutável (mutabilidade interior) e, se as regras forem quebradas, o programa entra em pânico.

1. borrow e borrow_mut

use std::cell::RefCell;

fn main() {
    let lista = RefCell::new(vec![1, 2, 3]);

    lista.borrow_mut().push(4);

    let tamanho = lista.borrow().len();
    println!("tamanho: {tamanho}");
    println!("lista: {:?}", lista.borrow());
}
$ cargo run

Repare: lista não é mut, mas recebeu um push. borrow() devolve um empréstimo de leitura (Ref) e borrow_mut() um de escrita (RefMut); os dois são devolvidos sozinhos no fim da expressão ou do escopo.

2. Quebrando a regra: pânico em tempo de execução

use std::cell::RefCell;

fn main() {
    let saldo = RefCell::new(100);
    let leitura = saldo.borrow();
    let mut escrita = saldo.borrow_mut();
    *escrita += 50;
    println!("{}", leitura);
}
$ cargo run
   Compiling panico v0.1.0 (/home/ana/projetos/panico)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/panico`

thread 'main' (303503) panicked at src/main.rs:6:29:
RefCell already borrowed
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace

O código compila, mas o RefCell percebe que já existe um empréstimo de leitura ativo e entra em pânico com RefCell already borrowed. A correção é encerrar a leitura antes (por exemplo, num bloco { }) ou usar try_borrow_mut, que devolve um Result em vez de dar pânico.

use std::cell::RefCell;

fn main() {
    let saldo = RefCell::new(100);
    let leitura = saldo.borrow();
    match saldo.try_borrow_mut() {
        Ok(mut s) => *s += 50,
        Err(e) => println!("não deu para escrever: {e}"),
    }
    println!("saldo lido: {}", leitura);
}

3. Rc<RefCell<T>>: compartilhado e modificável

O par mais famoso: Rc dá vários donos, RefCell dá a modificação.

use std::cell::RefCell;
use std::rc::Rc;

#[derive(Debug)]
struct Conta {
    saldo: i64,
}

struct Pessoa {
    nome: String,
    conta: Rc<RefCell<Conta>>,
}

impl Pessoa {
    fn gastar(&self, valor: i64) {
        self.conta.borrow_mut().saldo -= valor;
        println!("{} gastou {}", self.nome, valor);
    }
}

fn main() {
    let conta = Rc::new(RefCell::new(Conta { saldo: 1000 }));
    let ana = Pessoa { nome: "Ana".into(), conta: Rc::clone(&conta) };
    let beto = Pessoa { nome: "Beto".into(), conta: Rc::clone(&conta) };

    ana.gastar(300);
    beto.gastar(150);
    println!("{:?}", conta.borrow());
}
$ cargo run
   Compiling conta-conjunta v0.1.0 (/home/ana/projetos/conta-conjunta)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.11s
     Running `target/debug/conta-conjunta`
Ana gastou 300
Beto gastou 150
Conta { saldo: 550 }

O método gastar recebe &self (imutável), mas consegue mudar o saldo graças ao RefCell. As duas pessoas veem a mesma conta graças ao Rc.

4. Cell: para valores Copy

use std::cell::Cell;

struct Contador {
    chamadas: Cell<u32>,
}

impl Contador {
    fn registrar(&self) {
        self.chamadas.set(self.chamadas.get() + 1);
    }
}

fn main() {
    let c = Contador { chamadas: Cell::new(0) };
    c.registrar();
    c.registrar();
    c.registrar();
    println!("chamadas: {}", c.chamadas.get());
}
$ cargo run
   Compiling cell v0.1.0 (/home/ana/projetos/cell)

     Running `target/debug/cell`

Cell não empresta: ele copia o valor para fora (get) e substitui (set). Por isso nunca entra em pânico, mas só serve bem para tipos Copy como números e bool.

    r.anotar("compilou");

use std::cell::RefCell;

struct Registro {

impl Registro {

}

Resumo

  • RefCell permite modificar através de &self: mutabilidade interior.
  • borrow() lê, borrow_mut() escreve; quebrar a regra dá pânico em execução.
  • try_borrow_mut() devolve Result em vez de pânico.
  • Rc<RefCell<T>> = vários donos que podem modificar; Cell serve para tipos Copy.
