Testes com cargo test

O Rust vem com testes embutidos: você escreve funções marcadas com #[test] e roda todas com cargo test. Não precisa instalar nada. Os testes ficam ao lado do código, no mesmo arquivo, e o compilador só os inclui quando você está testando.

Você vai aprender
  • A escrever testes com #[test], assert!, assert_eq! e assert_ne!.
  • A ler a saída de um teste que passa e de um que falha.
  • #[should_panic], testes com Result, filtros e testes de integração na pasta tests/.

1. O primeiro teste

fn soma(a: i32, b: i32) -> i32 {
    a + b
}

fn main() {
    println!("{}", soma(2, 2));
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn soma_dois_numeros() {
        assert_eq!(soma(2, 3), 5);
    }

    #[test]
    fn soma_com_negativo() {
        assert_eq!(soma(-1, 1), 0);
    }
}

3. assert!, mensagens e should_panic

pub struct Idade(u8);

impl Idade {
    pub fn new(valor: i32) -> Idade {
        if !(0..=150).contains(&valor) {
            panic!("idade fora do intervalo: {valor}");
        }
        Idade(valor as u8)
    }
    pub fn maior_de_idade(&self) -> bool {
        self.0 >= 18
    }
}

fn main() {
    println!("{}", Idade::new(20).maior_de_idade());
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn adulto() {
        assert!(Idade::new(30).maior_de_idade(), "30 anos deveria ser maior de idade");
    }

    #[test]
    fn crianca() {
        assert_ne!(Idade::new(10).maior_de_idade(), true);
    }

    #[test]
    #[should_panic(expected = "fora do intervalo")]
    fn negativa_da_panic() {
        Idade::new(-5);
    }
}

#[should_panic] inverte o teste: ele passa só se o código der panic (e, com expected, só se a mensagem tiver aquele trecho).

4. Testes com Result e filtros

Um teste pode devolver Result e usar ?: se chegar um Err, o teste falha. cargo test conversao roda só os testes com “conversao” no nome (repare no 1 filtered out). Tudo depois de -- vai para o executável de testes, como o --list.

5. Testes de integração: a pasta tests/

Testes na pasta tests/ usam a sua biblioteca como um usuário de fora usaria, só pela parte pública:

pub fn eh_palindromo(s: &str) -> bool {
    let letras: Vec<char> = s.chars().filter(|c| c.is_alphanumeric()).flat_map(|c| c.to_lowercase()).collect();
    letras.iter().eq(letras.iter().rev())
}
use integracao::eh_palindromo;

#[test]
fn reconhece_palindromos() {
    assert!(eh_palindromo("Ame a ema"));
    assert!(eh_palindromo("A base do teto desaba"));
}

#[test]
fn recusa_frase_comum() {
    assert!(!eh_palindromo("Rust é legal"));
}

Resumo

  • Testes são funções #[test], normalmente num mod tests com #[cfg(test)].
  • assert!, assert_eq!, assert_ne!; a falha mostra left e right.
  • #[should_panic] espera um panic; testes podem devolver Result.
  • cargo test nome filtra; a pasta tests/ guarda testes de integração.
