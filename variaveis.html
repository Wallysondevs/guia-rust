Variáveis e mut

Em Rust, uma variável criada com let é imutável por padrão: depois de receber um valor, não muda mais. Para poder mudar, você pede explicitamente com mut. Parece estranho no começo, mas deixa o código mais fácil de entender: quem lê sabe na hora quais valores mudam.

Você vai aprender
  • let, let mut e o erro real quando você tenta mudar uma variável imutável.
  • O shadowing (sombreamento): criar uma nova variável com o mesmo nome.
  • Constantes com const e a diferença para let.

1. let: imutável por padrão

fn main() {
    let x = 5;
    println!("x vale {x}");
}
$ cargo run
   Compiling let v0.1.0 (/home/ana/projetos/let)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.10s
     Running `target/debug/let`
x vale 5

Agora tente mudar o valor:

fn main() {
    let x = 5;
    println!("x vale {x}");
    x = 6;
    println!("x vale {x}");
}
$ cargo run
   Compiling let-erro v0.1.0 (/home/ana/projetos/let-erro)
error[E0384]: cannot assign twice to immutable variable `x`
 --> src/main.rs:4:5
  |
2 |     let x = 5;
  |         - first assignment to `x`
3 |     println!("x vale {x}");
4 |     x = 6;
  |     ^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut x = 5;
  |         +++

For more information about this error, try `rustc --explain E0384`.
error: could not compile `let-erro` (bin "let-erro") due to 1 previous error

Este é o erro E0384: cannot assign twice to immutable variable (não dá para atribuir duas vezes a uma variável imutável). O compilador aponta a primeira atribuição, a segunda, e na linha help diz exatamente o que fazer: colocar mut. Para ler a explicação completa de qualquer erro, use rustc --explain E0384.

2. let mut: quando precisa mudar

fn main() {
    let mut pontos = 0;
    println!("início: {pontos}");
    pontos = pontos + 10;
    pontos += 5;
    println!("fim: {pontos}");
}
$ cargo run
   Compiling mut v0.1.0 (/home/ana/projetos/mut)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/mut`
início: 0
fim: 15

O += é um atalho para pontos = pontos + 5. Também existem -=, *=, /= e %=. Rust não tem ++ nem --.

3. Shadowing: o mesmo nome, uma variável nova

Você pode declarar let de novo com o mesmo nome. A nova variável “faz sombra” na antiga. Diferente de mut, o shadowing pode até trocar o tipo:

fn main() {
    let espacos = "   ";
    let espacos = espacos.len();
    println!("quantidade de espaços: {espacos}");

    let x = 5;
    {
        let x = x * 2;
        println!("dentro do bloco: {x}");
    }
    println!("fora do bloco: {x}");
}
$ cargo run
   Compiling shadowing v0.1.0 (/home/ana/projetos/shadowing)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.10s
     Running `target/debug/shadowing`
quantidade de espaços: 3
dentro do bloco: 10
fora do bloco: 5

Dentro do bloco { }, o x novo vale 10. Quando o bloco termina, ele some, e o x de fora (5) volta a valer. Com mut não daria para trocar texto por número:

fn main() {
    let mut espacos = "   ";
    espacos = espacos.len();
    println!("{espacos}");
}
$ cargo run
   Compiling mut-tipo v0.1.0 (/home/ana/projetos/mut-tipo)
error[E0308]: mismatched types
 --> src/main.rs:3:15
  |
2 |     let mut espacos = "   ";
  |                       ----- expected due to this value
3 |     espacos = espacos.len();
  |               ^^^^^^^^^^^^^ expected `&str`, found `usize`

For more information about this error, try `rustc --explain E0308`.
error: could not compile `mut-tipo` (bin "mut-tipo") due to 1 previous error

Erro E0308, mismatched types (tipos que não combinam): a variável foi criada como texto (&str) e o len() devolve um número (usize). Uma variável mut muda de valor, nunca de tipo.

4. Constantes: const

const SEGUNDOS_POR_HORA: u32 = 60 * 60;

fn main() {
    let horas = 3;
    println!("{} segundos", horas * SEGUNDOS_POR_HORA);
}
$ cargo run
   Compiling const v0.1.0 (/home/ana/projetos/const)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/const`
10800 segundos
  • Constantes usam const, nunca mut, e o tipo é obrigatório (aqui, u32).
  • O nome vai em MAIÚSCULAS_COM_SUBLINHADO, por convenção.
  • Podem ficar fora de funções e valem para o arquivo inteiro.
  • O valor precisa ser calculável na compilação.

5. Variável não usada: aviso, não erro

fn main() {
    let total = 100;
    let _rascunho = 7;
    println!("{total}");
}
$ cargo run
   Compiling nao-usada v0.1.0 (/home/ana/projetos/nao-usada)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.08s
     Running `target/debug/nao-usada`
100

Nenhum aviso aqui: começar o nome com _ diz ao compilador “eu sei que não uso esta variável”. Sem o _, ele avisaria com unused variable, como você viu na aula do cargo.

O que o erro E0384 quer dizer?

Missão: O programa abaixo não compila (é o erro E0384). Conserte-o para que imprima Saldo final: 150.

fn main() {
    let saldo = 100;
    saldo += 50;
    println!("Saldo final: {saldo}");
}

fn main() {
    let mut saldo = 100;
    saldo += 50;
    println!("Saldo final: {saldo}");
}

Missão: Use shadowing: crie let texto = "Rust"; e, na linha seguinte, uma nova variável texto com o tamanho dele (texto.len()). Imprima Tamanho: 4.

const MINUTOS_POR_DIA: u32 = 24 * 60;

Resumo

  • let cria variável imutável; let mut, mutável.
  • Mudar uma variável imutável é o erro E0384; o help sugere o mut.
  • Shadowing (let de novo) cria uma variável nova e pode trocar o tipo.
  • const exige tipo, usa MAIÚSCULAS e vale na compilação.
