Structs

Uma struct (estrutura) junta vários valores relacionados sob um nome, cada um com o seu rótulo. É como uma ficha de cadastro: nome, e-mail, idade. Diferente da tupla, cada campo tem nome, então o código fica muito mais legível.

Você vai aprender
  • A definir uma struct, criar instâncias e ler e mudar campos.
  • Os atalhos de inicialização e de atualização (..outra).
  • Structs de tupla, unit structs e o #[derive(Debug)] para imprimir.

1. Definindo e criando

struct Usuario {
    nome: String,
    email: String,
    idade: u32,
    ativo: bool,
}

fn main() {
    let mut ana = Usuario {
        nome: String::from("Ana"),
        email: String::from("ana@exemplo.com"),
        idade: 28,
        ativo: true,
    };
    ana.idade += 1;
    println!("{} <{}>, {} anos, ativo: {}", ana.nome, ana.email, ana.idade, ana.ativo);
}
$ cargo run
   Compiling struct v0.1.0 (/home/ana/projetos/struct)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.11s
     Running `target/debug/struct`
Ana <ana@exemplo.com>, 29 anos, ativo: true

Para mudar um campo, a instância inteira precisa ser mut: o Rust não deixa marcar só alguns campos como mutáveis. Nomes de struct usam CamelCase (Usuario, PedidoDeCompra).

2. Imprimindo: #[derive(Debug)]

Tente imprimir a struct inteira com {:?} sem preparar nada:

struct Ponto {
    x: i32,
    y: i32,
}

fn main() {
    let p = Ponto { x: 1, y: 2 };
    println!("{:?}", p);
}

O {:?} exige o trait Debug. O help e a note dizem a correção: colocar #[derive(Debug)] acima da struct, que gera o código de impressão automaticamente.

#[derive(Debug)]
struct Ponto {
    x: i32,
    y: i32,
}

fn main() {
    let p = Ponto { x: 1, y: 2 };
    println!("{:?}", p);
    println!("{:#?}", p);
    dbg!(&p);
}

O dbg! imprime na saída de erro o arquivo, a linha, a expressão e o valor. É ótimo para depurar.

Repare no warning do começo: os campos x e y “nunca são lidos”. O compilador avisa sobre código morto (dead code) e, de propósito, não conta a leitura que o Debug faz (a note explica isso). Num programa de verdade, os campos são usados em algum lugar e o aviso some, como nos próximos exemplos.

3. Atalhos: inicialização e atualização

#[derive(Debug)]
struct Config {
    tema: String,
    fonte: u32,
    som: bool,
}

fn criar(tema: String, fonte: u32) -> Config {
    Config { tema, fonte, som: true }
}

fn main() {
    let padrao = criar(String::from("claro"), 14);
    let escuro = Config {
        tema: String::from("escuro"),
        ..padrao
    };
    println!("{:?}", escuro);
    println!("tema {} | fonte {} | som {}", escuro.tema, escuro.fonte, escuro.som);
}
$ cargo run
   Compiling atalhos v0.1.0 (/home/ana/projetos/atalhos)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.13s
     Running `target/debug/atalhos`
Config { tema: "escuro", fonte: 14, som: true }
tema escuro | fonte 14 | som true

Quando a variável tem o mesmo nome do campo, basta escrever tema em vez de tema: tema. O ..padrao preenche os campos que faltam com os de outra instância. Atenção: se um campo copiado for uma String, ele é movido, e a instância antiga perde aquele campo.

4. Structs de tupla e unit structs

#[derive(Debug)]
struct Cor(u8, u8, u8);
#[derive(Debug)]
struct Metros(f64);
#[derive(Debug)]
struct Marcador;

fn main() {
    let laranja = Cor(255, 140, 0);
    let distancia = Metros(42.5);
    println!("{:?} vermelho={} verde={} azul={}", laranja, laranja.0, laranja.1, laranja.2);
    println!("{:?} = {} m", distancia, distancia.0);
    println!("{:?}", Marcador);
}
$ cargo run
   Compiling tuple-struct v0.1.0 (/home/ana/projetos/tuple-struct)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/tuple-struct`
Cor(255, 140, 0) vermelho=255 verde=140 azul=0
Metros(42.5) = 42.5 m
Marcador

Structs de tupla têm campos sem nome (.0, .1). São úteis para dar um tipo próprio a um valor: Metros(42.5) não pode ser confundido com um f64 qualquer. A unit struct (Marcador) não tem campos e aparece com traits, mais adiante.

5. Quando dá errado: esquecer um campo

struct Produto {
    nome: String,
    preco: f64,
    estoque: u32,
}

fn main() {
    let p = Produto {
        nome: String::from("caneta"),
        preco: 2.5,
    };
    println!("{}", p.nome);
}
$ cargo run
   Compiling campo-faltando v0.1.0 (/home/ana/projetos/campo-faltando)
error[E0063]: missing field `estoque` in initializer of `Produto`
 --> src/main.rs:8:13
  |
8 |     let p = Produto {
  |             ^^^^^^^ missing `estoque`

For more information about this error, try `rustc --explain E0063`.
error: could not compile `campo-faltando` (bin "campo-faltando") due to 1 previous error

Erro E0063: todo campo precisa de valor. Em Rust não existe campo “nulo” por esquecimento.

Missão: Crie a struct de tupla Celsius(f64) e uma função fn para_fahrenheit(c: Celsius) -> f64 (F = C × 9 / 5 + 32). Imprima 25 °C = 77 °F.

fn main() {
}

struct Celsius(f64);

fn para_fahrenheit(c: Celsius) -> f64 {
    c.0 * 9.0 / 5.0 + 32.0
}

fn main() {
    let t = Celsius(25.0);
    let c = t.0;
    println!("{} °C = {} °F", c, para_fahrenheit(t));
}

Resumo

  • struct Nome { campo: Tipo, … }; crie com Nome { campo: valor, … }.
  • Todo campo precisa de valor (E0063); para mudar campos, a instância é mut.
  • #[derive(Debug)] libera {:?}, {:#?} e dbg!.
  • Atalhos: Nome { campo } e ..outra; structs de tupla: struct Cor(u8, u8, u8).
