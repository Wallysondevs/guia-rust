Threads

Uma thread é um fluxo de execução que roda ao mesmo tempo que outros, dentro do mesmo programa. Rust promete “concorrência sem medo”: os mesmos donos e empréstimos que você já conhece impedem, na compilação, que duas threads estraguem o mesmo dado.

1. Criando uma thread

use std::thread;
use std::time::Duration;

fn main() {
    let handle = thread::spawn(|| {
        for i in 1..=3 {
            println!("  thread extra: passo {i}");
            thread::sleep(Duration::from_millis(10));
        }
    });

    for i in 1..=3 {
        println!("main: passo {i}");
        thread::sleep(Duration::from_millis(10));
    }

    handle.join().unwrap();
    println!("as duas terminaram");
}

thread::spawn(closure)
cria a thread e já começa a rodar a closure.
handle
um JoinHandle, a “alça” da thread.
handle.join()
espera a thread terminar. Sem isso, quando o main acaba, o programa encerra e mata as outras threads.
A ordem muda a cada execução. Quem decide qual thread roda é o sistema operacional. A saída acima é de uma execução real; rode de novo e as linhas podem se intercalar de outro jeito.

2. move: levando dados para a thread

use std::thread;

fn main() {
    let nomes = vec!["Ana", "Bia", "Caio"];
    let h = thread::spawn(|| {
        println!("{:?}", nomes);
    });
    h.join().unwrap();
}

A thread pode viver mais que a função que a criou, então emprestar nomes seria perigoso: o vetor poderia ser liberado com a thread ainda usando. O compilador sugere a solução: move transfere a posse para dentro da closure.

use std::thread;

fn main() {
    let nomes = vec!["Ana", "Bia", "Caio"];
    let h = thread::spawn(move || {
        println!("a thread agora é dona de {:?}", nomes);
        nomes.len()
    });
    let total = h.join().unwrap();
    println!("a thread devolveu {total}");
}
$ cargo run

Repare também no retorno: o valor que a closure devolve chega pelo join(), dentro de um Result (que é Err se a thread entrou em pânico).

3. Várias threads e seus resultados

use std::thread;

fn main() {
    let mut handles = Vec::new();
    for id in 1..=4u64 {
        handles.push(thread::spawn(move || {
            let soma: u64 = (1..=id * 1000).sum();
            (id, soma)
        }));
    }
    for h in handles {
        let (id, soma) = h.join().unwrap();
        println!("thread {id}: soma de 1 a {} = {soma}", id * 1000);
    }
}

4. thread::scope: emprestar sem move

Desde o Rust 1.63, thread::scope cria threads que com certeza terminam antes do fim do bloco. Por isso elas podem emprestar variáveis locais sem move:

use std::thread;

fn main() {
    let numeros = vec![1, 2, 3, 4, 5, 6, 7, 8];
    let (esq, dir) = numeros.split_at(numeros.len() / 2);

    let (a, b) = thread::scope(|s| {
        let h1 = s.spawn(|| esq.iter().sum::<i32>());
        let h2 = s.spawn(|| dir.iter().sum::<i32>());
        (h1.join().unwrap(), h2.join().unwrap())
    });

    println!("metade 1 = {a}, metade 2 = {b}, total = {}", a + b);
    println!("o vetor continua aqui: {:?}", numeros);
}

5. Pânico numa thread

use std::thread;

fn main() {
    let h = thread::spawn(|| {
        let v: Vec<i32> = Vec::new();
        v[0]
    });
    match h.join() {
        Ok(v) => println!("valor: {v}"),
        Err(_) => println!("a thread entrou em pânico, mas o main continua"),
    }
}

Missão: Use thread::scope para procurar o maior número de dados numa thread (emprestando o vetor, sem move) e imprima maior: 42.

use std::thread;

fn main() {
    let dados = vec![7, 42, 3, 19];
    let maior = 0;
    println!("maior: {maior}");
}

use std::thread;

fn main() {
    let dados = vec![7, 42, 3, 19];
    let maior = thread::scope(|s| {
        let h = s.spawn(|| *dados.iter().max().unwrap());
        h.join().unwrap()
    });
    println!("maior: {maior}");
}

Resumo

  • thread::spawn cria uma thread; join() espera e devolve o resultado.
  • A ordem entre threads não é garantida.
  • move passa a posse das variáveis para a thread (evita o E0373).
  • thread::scope deixa as threads emprestarem variáveis locais.
