Ownership (posse)

Ownership (posse) é a ideia que faz o Rust ser seguro sem coletor de lixo. São três regras, conferidas pelo compilador. No começo elas causam muitos erros; depois de um tempo, viram um jeito natural de pensar em quem é responsável por cada dado.

As três regras
  1. Cada valor tem uma variável que é a sua dona.
  2. Só pode haver um dono por vez.
  3. Quando o dono sai de escopo, o valor é liberado (drop).

1. Escopo: o valor vive enquanto o dono vive

fn main() {
    {
        let s = String::from("olá");
        println!("dentro: {s}");
    } // aqui o s sai de escopo e a String é liberada
    println!("fora do bloco");
}
$ cargo run
   Compiling escopo v0.1.0 (/home/ana/projetos/escopo)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/escopo`
dentro: olá
fora do bloco

Uma String guarda o texto na memória heap (a área de memória para dados de tamanho variável). Quando s sai de escopo, no }, o Rust libera essa memória automaticamente. Ninguém precisa chamar free.

2. Move: passar a posse adiante

fn main() {
    let s1 = String::from("Rust");
    let s2 = s1;
    println!("{s1}");
    println!("{s2}");
}
$ cargo run

error: could not compile `move` (bin "move") due to 1 previous error

Este é o erro mais famoso do Rust: E0382, borrow of moved value. O let s2 = s1; moveu a posse da String para s2 (regra 2: um dono só). Depois disso, s1 não vale mais nada. Por quê? Se os dois fossem donos, os dois tentariam liberar a mesma memória no fim (o bug double free, comum em C). O compilador explica tudo: onde o valor foi movido, onde foi usado depois, e por que (String não implementa o trait Copy).

3. clone: uma cópia de verdade

Se você quer dois valores independentes, peça uma cópia explícita com .clone(), como o próprio help sugeriu:

fn main() {
    let s1 = String::from("Rust");
    let s2 = s1.clone();
    println!("s1 = {s1}, s2 = {s2}");
}
$ cargo run
   Compiling clone v0.1.0 (/home/ana/projetos/clone)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/clone`
s1 = Rust, s2 = Rust

O clone copia o texto inteiro para outro lugar da memória. É explícito de propósito: quando você lê .clone(), sabe que ali há um custo.

4. Tipos Copy: números não se movem

fn main() {
    let a = 5;
    let b = a;
    println!("a = {a}, b = {b}");
    let t = (1, 'x', true);
    let u = t;
    println!("{:?} {:?}", t, u);
}
$ cargo run
   Compiling copy v0.1.0 (/home/ana/projetos/copy)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/copy`
a = 5, b = 5
(1, 'x', true) (1, 'x', true)

Inteiros, floats, bool, char e tuplas só com esses tipos são Copy: cabem inteiros na pilha (stack) e copiar é barato, então a atribuição copia em vez de mover. String, Vec e outros que guardam dados no heap não são Copy.

Passar uma String para uma função move a posse para o parâmetro. Quando a função termina, o valor é liberado, e s não pode ser usado de novo. Uma saída é a função devolver a posse:

fn mostrar(texto: String) -> String {
    println!("mostrando: {texto}");
    texto
}

fn main() {
    let s = String::from("dado");
    let s = mostrar(s);
    let s = mostrar(s);
    println!("ainda tenho: {s}");
}
$ cargo run

Funciona, mas é trabalhoso ficar devolvendo tudo. Na próxima aula você vê o jeito certo: emprestar com &, sem passar a posse.

6. Vendo o drop acontecer

Dá para observar a regra 3 implementando o trait Drop (você vê traits no Nível 2; aqui basta ler a saída):

struct Recurso(&'static str);

impl Drop for Recurso {
    fn drop(&mut self) {
        println!("liberando {}", self.0);
    }
}

fn main() {
    let _a = Recurso("A");
    {
        let _b = Recurso("B");
        println!("fim do bloco interno");
    }
    let c = Recurso("C");
    drop(c);
    println!("fim do main");
}
$ cargo run
   Compiling drop v0.1.0 (/home/ana/projetos/drop)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/drop`
fim do bloco interno
liberando B
liberando C
fim do main
liberando A

O B é liberado no fim do bloco; o C, na hora do drop(c) (a função drop recebe a posse e o valor morre ali); o A, só no fim do main.

Resumo

  • Cada valor tem um dono; só um por vez; quando o dono sai de escopo, o valor é liberado.
  • Atribuir ou passar para função move a posse (E0382 se usar depois).
  • .clone() faz uma cópia explícita; tipos Copy (números, bool, char) são copiados sozinhos.
