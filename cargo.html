Projetos com cargo

O cargo é o gerente de projetos do Rust. Com ele você cria a estrutura de pastas, compila, roda, testa e baixa bibliotecas. Quase todo projeto Rust do mundo é organizado do mesmo jeito, então o que você aprender aqui serve para qualquer um.

Você vai aprender
  • A criar um projeto com cargo new e a ler o Cargo.toml.
  • A diferença entre cargo build, cargo run e cargo check.
  • Onde fica o executável e o que muda com --release.

1. Criando o projeto

$ cargo new ola
    Creating binary (application) `ola` package
note: see more `Cargo.toml` keys and their definitions at https://doc.rust-lang.org/cargo/reference/manifest.html
$ ls -a ola
.
..
.git
.gitignore
Cargo.toml
src
$ cat ola/Cargo.toml
[package]
name = "ola"
version = "0.1.0"
edition = "2024"

[dependencies]
$ cat ola/src/main.rs
fn main() {
    println!("Hello, world!");
}

O cargo new criou uma pasta com tudo pronto, inclusive um repositório git (a pasta .git e o .gitignore). O programa inicial já é o clássico “Hello, world!”.

[package]
os dados do projeto (o pacote).
name
o nome, que também vira o nome do executável.
version
a versão do seu programa.
edition
a edição da linguagem (2015, 2018, 2021, 2024): regras de sintaxe que o projeto segue.
[dependencies]
as bibliotecas de que o projeto precisa (por enquanto, nenhuma).

2. Compilar e rodar: cargo run

Dentro da pasta do projeto, cargo run compila (se precisar) e roda:

$ cargo new ola-run
    Creating binary (application) `ola-run` package
note: see more `Cargo.toml` keys and their definitions at https://doc.rust-lang.org/cargo/reference/manifest.html
$ cd ola-run
$ cargo run
   Compiling ola-run v0.1.0 (/home/ana/projetos/ola-run)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.09s
     Running `target/debug/ola-run`
Hello, world!
$ cargo run
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.00s
     Running `target/debug/ola-run`
Hello, world!

Repare nas três linhas que o cargo escreve antes da saída do programa: Compiling (compilando), Finished (terminou, com o perfil dev, sem otimização e com informação de depuração) e Running (rodando o executável). Na segunda vez não há Compiling: nada mudou, então o cargo reaproveitou o executável.

3. Só compilar: cargo build

$ cargo new ola-build
    Creating binary (application) `ola-build` package
note: see more `Cargo.toml` keys and their definitions at https://doc.rust-lang.org/cargo/reference/manifest.html
$ cd ola-build
$ cargo build
   Compiling ola-build v0.1.0 (/home/ana/projetos/ola-build)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.08s
$ ls target/debug
build
examples
incremental
ola-build
ola-build.d
$ ./target/debug/ola-build
Hello, world!

O executável fica em target/debug/. A pasta target guarda tudo que o compilador gera e pode ser apagada sem medo (cargo clean): o cargo recria na próxima compilação.

4. Conferir sem gerar executável: cargo check

Quando você só quer saber se o código compila, o cargo check é mais rápido: ele faz todas as conferências do compilador, mas não gera o executável. É o comando que mais se usa enquanto se escreve código.

fn main() {
    let idade = 30;
    println!("Olá!");
}
$ cargo check
    Checking ola-check v0.1.0 (/home/ana/projetos/ola-check)
warning: unused variable: `idade`
 --> src/main.rs:2:9
  |
2 |     let idade = 30;
  |         ^^^^^ help: if this is intentional, prefix it with an underscore: `_idade`
  |
  = note: `#[warn(unused_variables)]` (part of `#[warn(unused)]`) on by default

warning: `ola-check` (bin "ola-check") generated 1 warning (run `cargo fix --bin "ola-check" -p ola-check` to apply 1 suggestion)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.04s

O código compila (Finished), mas o compilador deixou um warning, um aviso: a variável idade nunca foi usada. Aviso não impede a compilação, mas vale ler. A linha help até sugere a correção.

5. A versão otimizada: --release

fn main() {
    println!("versão otimizada");
}
$ cargo build --release
   Compiling ola-release v0.1.0 (/home/ana/projetos/ola-release)
    Finished `release` profile [optimized] target(s) in 0.07s
$ ls target
CACHEDIR.TAG
release

Com --release o perfil muda para release (optimized) e o executável vai para target/release/. A compilação demora mais e o programa fica bem mais rápido. Use --release para medir desempenho e para entregar o programa; no dia a dia, o padrão (dev) compila mais depressa.

Quando dá errado: fora da pasta do projeto

$ cargo run
error: could not find `Cargo.toml` in `/home/ana` or any parent directory

O cargo procura o Cargo.toml na pasta atual e nas de cima. Fora de um projeto, ele não acha e avisa. Entre na pasta com cd e rode de novo.

Referência rápida

Você digitaO que faz
cargo new nomeCria um projeto de programa (binário).
cargo new --lib nomeCria um projeto de biblioteca.
cargo runCompila se precisar e roda.
cargo buildSó compila (em target/debug).
cargo checkConfere se compila, sem gerar executável.
cargo build --releaseCompila otimizado (em target/release).
cargo cleanApaga a pasta target.

Resumo

  • cargo new cria a estrutura: Cargo.toml + src/main.rs + git.
  • cargo run compila e roda; cargo build só compila; cargo check só confere.
  • Executáveis em target/debug ou, com --release, em target/release.
  • Warnings não impedem a compilação, mas costumam apontar algo esquecido.
