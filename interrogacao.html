O operador ?

Quando uma função chama outras que podem falhar, escrever um match para cada chamada cansa. O operador ? resolve isso: colocado depois de um Result, ele abre o Ok e, se for Err, devolve o erro na hora para quem chamou a função.

Você vai aprender
  • O que o ? faz, comparando com o match equivalente.
  • Usar ? com Option e no main.
  • Converter erros automaticamente com From, e o erro de usar ? onde não dá.

1. Antes e depois

As duas funções abaixo fazem a mesma coisa:

use std::num::ParseIntError;

fn somar_com_match(a: &str, b: &str) -> Result<i32, ParseIntError> {
    let x = match a.parse::<i32>() {
        Ok(v) => v,
        Err(e) => return Err(e),
    };
    let y = match b.parse::<i32>() {
        Ok(v) => v,
        Err(e) => return Err(e),
    };
    Ok(x + y)
}

fn somar(a: &str, b: &str) -> Result<i32, ParseIntError> {
    let x = a.parse::<i32>()?;
    let y = b.parse::<i32>()?;
    Ok(x + y)
}

fn main() {
    println!("{:?}", somar_com_match("2", "3"));
    println!("{:?}", somar("2", "3"));
    println!("{:?}", somar("2", "três"));
}

O ? é exatamente aquele match: Ok(v) vira v; Err(e) vira return Err(e). O código fica com cara de “caminho feliz”, e os erros sobem sozinhos.

3. ? com Option

fn inicial_do_segundo(nomes: &[&str]) -> Option<char> {
    let segundo = nomes.get(1)?;

O ? precisa ter para onde devolver o erro. O main padrão devolve (), então não dá. Mas o main também pode devolver um Result:

use std::num::ParseIntError;

fn main() -> Result<(), ParseIntError> {
    let a: i32 = "10".parse()?;
    println!("a = {a}");
    let b: i32 = "dez".parse()?;
    println!("b = {b}");
    Ok(())
}

5. Erros diferentes numa função só: From

E se uma função pode falhar lendo arquivo (io::Error) e convertendo número (ParseIntError)? Crie um enum de erros e implemente From para cada um: o ? usa o From para converter sozinho.

use std::fs;
use std::io;
use std::num::ParseIntError;

#[derive(Debug)]
enum ErroApp {
    Arquivo(io::Error),
    Numero(ParseIntError),
}

impl From<io::Error> for ErroApp {
    fn from(e: io::Error) -> Self {
        ErroApp::Arquivo(e)
    }
}

impl From<ParseIntError> for ErroApp {
    fn from(e: ParseIntError) -> Self {
        ErroApp::Numero(e)
    }
}

fn ler_e_somar_um(caminho: &str) -> Result<i32, ErroApp> {
    let texto = fs::read_to_string(caminho)?;
    let n: i32 = texto.trim().parse()?;
    Ok(n + 1)
}

fn main() {
    for caminho in ["numero.txt", "ruim.txt", "nada.txt"] {
        match ler_e_somar_um(caminho) {
            Ok(n) => println!("{caminho}: {n}"),
            Err(ErroApp::Arquivo(e)) => println!("{caminho}: erro de arquivo: {e}"),
            Err(ErroApp::Numero(e)) => println!("{caminho}: erro de número: {e}"),
        }
    }
}

Atalho para programas pequenos

O tipo Box<dyn std::error::Error> aceita qualquer erro, sem precisar de enum: fn main() -> Result<(), Box<dyn std::error::Error>>. Você entende o Box e o dyn no Nível 3; por enquanto, saiba que ele existe.

Resumo

  • expr?: abre o Ok/Some ou devolve o Err/None na hora.
  • Só funciona em funções que devolvem Result ou Option (o main pode devolver Result).
  • Com impl From<ErroX> for MeuErro, o ? converte os erros sozinho.
