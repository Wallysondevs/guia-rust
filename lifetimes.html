Lifetimes

Um lifetime (tempo de vida) é o trecho do programa em que uma referência é válida. O compilador confere os lifetimes sempre, mas quase sempre descobre sozinho. Às vezes ele não consegue adivinhar a relação entre as referências e pede que você a escreva com um nome como 'a. Anotar não muda quanto tempo nada vive: só explica ao compilador o que já é verdade.

Você vai aprender
  • Por que o compilador pede um lifetime (E0106) e como anotar com 'a.
  • O erro E0597 (does not live long enough) e o que ele protege.
  • Structs com referências, as regras de elisão e o 'static.

1. O problema

fn mais_longa(a: &str, b: &str) -> &str {
    if a.len() >= b.len() { a } else { b }
}

fn main() {
    println!("{}", mais_longa("Rust", "Python"));
}

A função devolve uma referência, mas para qual dos dois textos? Depende da execução. O compilador precisa saber por quanto tempo o resultado vale, e a assinatura não diz. O help sugere a anotação.

2. Anotando com 'a

fn mais_longa<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() { a } else { b }
}

fn main() {
    let s1 = String::from("abacaxi");
    let resultado;
    {
        let s2 = String::from("kiwi");
        resultado = mais_longa(&s1, &s2);
        println!("dentro: {resultado}");
    }
    println!("fim");
}
$ cargo run
   Compiling com-lifetime v0.1.0 (/home/ana/projetos/com-lifetime)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.11s
     Running `target/debug/com-lifetime`
dentro: abacaxi
fim
<'a>
declara um lifetime chamado 'a (como um generic).
a: &'a str, b: &'a str
as duas entradas vivem pelo menos durante 'a.
-> &'a str
o resultado vale enquanto as duas entradas valerem.

Na prática, 'a vira o menor dos dois tempos de vida. Por isso o uso dentro do bloco funciona.

3. Quando dá errado: E0597

Agora, usando o resultado depois que s2 morreu:

fn mais_longa<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() { a } else { b }
}

fn main() {
    let s1 = String::from("abacaxi");
    let resultado;
    {
        let s2 = String::from("kiwi");
        resultado = mais_longa(&s1, &s2);
    }
    println!("{resultado}");
}
$ cargo run
   Compiling e0597 v0.1.0 (/home/ana/projetos/e0597)
error[E0597]: `s2` does not live long enough
  --> src/main.rs:10:37
   |
 9 |         let s2 = String::from("kiwi");
   |             -- binding `s2` declared here
10 |         resultado = mais_longa(&s1, &s2);
   |                                     ^^^ borrowed value does not live long enough
11 |     }
   |     - `s2` dropped here while still borrowed
12 |     println!("{resultado}");
   |                --------- borrow later used here

For more information about this error, try `rustc --explain E0597`.
error: could not compile `e0597` (bin "e0597") due to 1 previous error

Neste caso, o resultado seria s1 (o maior), que ainda existe. Mas o compilador não roda o programa: pela assinatura, o resultado pode ser s2, que morreu no }. Ele recusa o código que poderia usar memória liberada. Esse é o erro E0597, borrowed value does not live long enough.

4. Structs que guardam referências

struct Trecho<'a> {
    texto: &'a str,
}

impl<'a> Trecho<'a> {
    fn primeira_palavra(&self) -> &'a str {
        self.texto.split_whitespace().next().unwrap_or("")
    }
}

fn main() {
    let livro = String::from("Era uma vez um caranguejo. Ele gostava de Rust.");
    let primeira_frase = livro.split('.').next().unwrap();
    let t = Trecho { texto: primeira_frase };
    println!("trecho: '{}'", t.texto);
    println!("primeira palavra: {}", t.primeira_palavra());
}
$ cargo run
   Compiling struct-ref v0.1.0 (/home/ana/projetos/struct-ref)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.13s
     Running `target/debug/struct-ref`
trecho: 'Era uma vez um caranguejo'
primeira palavra: Era

Uma struct com referência precisa do lifetime: Trecho<'a> significa “um Trecho não pode viver mais que o texto que ele empresta”. Se você tentar guardar o Trecho depois que livro morreu, é erro de compilação.

5. Quando não precisa anotar: elisão

Na maioria das funções você não escreve lifetimes, porque o compilador aplica três regras (elisão):

  1. Cada parâmetro referência ganha o seu próprio lifetime.
  2. Se há um só parâmetro referência, o retorno usa o lifetime dele.
  3. Se um dos parâmetros é &self ou &mut self, o retorno usa o lifetime de self.
fn primeira(s: &str) -> &str {
    s.split(' ').next().unwrap_or(s)
}

const SAUDACAO: &'static str = "olá";

fn main() {
    println!("{}", primeira("bom dia"));
    let fixo: &'static str = "texto gravado no programa";
    println!("{fixo} / {SAUDACAO}");
}
$ cargo run
   Compiling elisao v0.1.0 (/home/ana/projetos/elisao)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.10s
     Running `target/debug/elisao`
bom
texto gravado no programa / olá

primeira tem um parâmetro só, então a regra 2 resolve. O 'static é o lifetime especial de quem vive o programa inteiro, como os literais de texto. Cuidado com a tentação de colocar 'static para calar o compilador: quase sempre o certo é devolver um valor com dono (String).

Resumo

  • Lifetime = por quanto tempo uma referência vale; anotar só descreve, não estende.
  • Funções que devolvem referência de várias entradas precisam de 'a (E0106).
  • Usar uma referência depois que o dono morreu é o E0597.
  • Structs com referências levam <'a>; 'static é o programa inteiro.
