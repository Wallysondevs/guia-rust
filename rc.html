Rc<T>: vários donos

A regra do ownership diz: cada valor tem um dono. Às vezes, porém, um valor precisa ser compartilhado de verdade: vários nós de um grafo apontando para o mesmo nó, várias partes do programa lendo a mesma configuração. O Rc<T> (reference counted) resolve isso: ele conta quantos donos existem e só libera o valor quando o último sai de escopo.

1. O problema

#[derive(Debug)]
enum Lista {
    No(i32, Box<Lista>),
    Fim,
}

use Lista::{Fim, No};

fn main() {
    let comum = No(5, Box::new(No(10, Box::new(Fim))));
    let a = No(3, Box::new(comum));
    let b = No(4, Box::new(comum));
    println!("{:?}\n{:?}", a, b);
}

2. Compartilhando com Rc

use std::rc::Rc;

#[allow(dead_code)]
#[derive(Debug)]
enum Lista {
    No(i32, Rc<Lista>),
    Fim,
}

use Lista::{Fim, No};

fn main() {
    let comum = Rc::new(No(5, Rc::new(No(10, Rc::new(Fim)))));
    println!("donos de comum: {}", Rc::strong_count(&comum));
    let a = No(3, Rc::clone(&comum));
    println!("depois de a: {}", Rc::strong_count(&comum));
    {
        let b = No(4, Rc::clone(&comum));
        println!("depois de b: {}", Rc::strong_count(&comum));
        println!("b = {:?}", b);
    }
    println!("b saiu de escopo: {}", Rc::strong_count(&comum));
    println!("a = {:?}", a);
}

O #[allow(dead_code)] só cala um aviso: os campos são lidos apenas pelo {:?}, e o compilador não conta o Debug derivado como “uso”.

Rc::new(v)
cria o valor no heap com contador 1.
Rc::clone(&r)
não copia o valor: cria outro ponteiro e soma 1 no contador. É barato.
Rc::strong_count(&r)
mostra quantos donos existem.
fim de escopo
cada Rc que sai de escopo subtrai 1; ao chegar em 0, o valor é liberado.
Por que Rc::clone(&x) e não x.clone()? Os dois fazem o mesmo. A convenção Rc::clone deixa claro para quem lê que é só um contador subindo, não uma cópia cara.

3. Vendo a liberação com Drop

use std::rc::Rc;

struct Recurso(&'static str);

impl Drop for Recurso {
    fn drop(&mut self) {
        println!("liberando {}", self.0);
    }
}

fn main() {
    let r1 = Rc::new(Recurso("config"));
    let r2 = Rc::clone(&r1);
    println!("donos: {}", Rc::strong_count(&r1));
    drop(r1);
    println!("r1 foi embora, donos: {}", Rc::strong_count(&r2));
    drop(r2);
    println!("fim do main");
}
$ cargo run

O trait Drop roda código quando um valor é destruído. O recurso só foi liberado quando o último dono (r2) foi embora.

4. Os limites do Rc

Rc é só leitura

use std::rc::Rc;

fn main() {
    let placar = Rc::new(vec![1, 2]);
    let outro = Rc::clone(&placar);
    outro.push(3);
    println!("{:?}", placar);
}
$ cargo run
   Compiling rc-mut v0.1.0 (/home/ana/projetos/rc-mut)
error[E0596]: cannot borrow data in an `Rc` as mutable
 --> src/main.rs:6:5
  |
6 |     outro.push(3);
  |     ^^^^^ cannot borrow as mutable
  |

For more information about this error, try `rustc --explain E0596`.
error: could not compile `rc-mut` (bin "rc-mut") due to 1 previous error

Se dois donos pudessem modificar o valor livremente, voltaríamos aos problemas que o borrow checker evita. Para modificar um valor compartilhado, combine com RefCell (próxima aula).

Rc não atravessa threads

O contador do Rc não é atômico, então o compilador proíbe mandá-lo para outra thread (o tipo não implementa Send). Entre threads, use Arc, que você verá na aula de Arc e Mutex.

Resumo

  • Rc<T> permite vários donos de um mesmo valor, contando as referências.
  • Rc::clone é barato: só soma 1 no contador.
  • O valor é liberado quando o contador chega a zero (veja com Drop).
  • Rc só dá acesso de leitura e não pode ir para outra thread.
